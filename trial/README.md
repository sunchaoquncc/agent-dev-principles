# 在真实项目试用本指导

协议v2 · 2026-10-18 · 配套候选v0.16。目标是判断哪些指导能改善项目，哪些无用、难用或造成退化；不以采用条数或改动规模评定成功。

## 放在哪里，怎么开始

把本仓库克隆到业务项目旁边的独立目录，例如同一父目录下的my-agent-project和agent-dev-principles。不覆盖业务项目已有AGENTS.md，不把本库放在业务项目的父目录。原项目规则和用户要求优先，本库只是候选参考。不要整包注入目标业务Agent的system prompt。

保存项目当前版本、未提交差异和可回退点；保留用户改动，不清理或重置。记录指导版本和Git提交SHA（git -C <指导目录> rev-parse HEAD），试验中固定版本。RELEASE_MANIFEST.json列出发布文件及SHA-256，哈希只确认文件完整，不证明有效。

在业务项目开发助手会话中粘贴[任务说明](TASK_PROMPT.md)，填写路径。默认先离线，无需API Key；已有明确预算/测试授权按其范围继续，不重复索要确认。收费范围未明确时先完成离线工作，再提出具体试验。

## 围绕实际任务，选择性采纳

有明确待办或失败时，只审当前问题和受影响的输入、调用、消费或输出链。尚无明确问题且用户希望整体审查时，才概览任务质量、职责、提示/解析、信息、退出和评测，再选值得处理的点。权限与数据边界仍按实际能力检查；不为覆盖全库新增功能。

先保存已有结果和初步诊断，再读核心的决策路由及相关章节；没有日志就检查实际代码/产物，推断单列。只有会改变选择的缺口才继续扩读，已知无关章节直接略过。无需为研究重新跑一遍业务，也不要求各章节逐项写“不适用”。

首轮可处理一个有证据、可回退的改动，也可判断暂不改；没有理由时不凑1—2项。复用正常、失败和边界产物，合成反例明确标注，不能当真实发生率。关注指导改变了什么判断，不以采用数量验收。

## 两层验证

**默认低成本前后试用。** 先保存现状结果和助手未参考指导时的初步诊断，再阅读指导，记录新增/改变的判断。比较改动后的业务输出、成本与退化。它能发现项目局部收益，不能将全部收益归因于本库：普通调试、额外时间和新测试也可能改善结果。已接触指导时如实标记，不补造“未读指导”的诊断；已读指导的同一会话不能冒充无指导对照。

**需要更强归因时再做独立对照。** 从同一项目快照，在独立目录、新会话，以同一任务、开发模型/工具/时间和调用预算比较“普通开发改进”和“额外借助指导改进”。对照组只用项目原有规则，先完成且不接收实验组计划/产物；实验组按需读本库。共同冻结的样例评测，候选实现不互相复制，评审尽量不知道分组。这个模式额外计费，单次开发结果仍有随机性，不代表跨项目普遍收益；首轮不默认开启。

业务运行比较固定模型/版本、输入、工具状态与数据；记录缓存、顺序及不可控变化。开发阶段与业务运行成本分列。仅在外部状态可恢复时比较同检查点续跑；真实写操作用沙箱或替身。

## 费用和验收

先免费检查解析、契约、格式和已知错误产物，再决定模型调用。样例按当前决定和失败后果选取，不设固定数量门槛。需要判断复用或泛化时，保留未参与调优的例子；已用于调优的不能继续称留出。一次性产物按当前要求验收，不为留出另造任务。

一次任务可多次API请求，输入/输出/推理、调优、评分、重试、回查和收费工具全计预算。执行前核实际服务价格和可落实的调用限制；支持时设置服务端费用限制，调用侧按最坏可计用量预留，剩余不足一对不启动。价格或硬限不明时缩小范围或只离线，不能凭Key存在认为额度无限。

先明确当前产物的验收依据；做前后质量比较时按任务标准盲判并抽查持平组，少量样本逐例报告。质量、事实/约束、真实usage、延迟、维护及人工负担一起记录，未知写未知。到预算上限、关键退化、无法判定或继续试验不影响决策时收口；保留阴性和回退理由，不改评分口径凑成功。未验证改动不自动部署或合并。

## 怎样反馈

在业务项目本地复制[反馈模板](FEEDBACK_TEMPLATE.md)为knowledge-trial-feedback.md，引用已有diff/日志，不另造重复台账。保留本地完整证据，另生成脱敏版：项目可用代号，Key、个人资料和私有prompt全文不公开；脱敏后无法判断时明确缺证据。

回执先写清“原本怎样做、指导改变了什么、结果与额外负担、保留或撤回什么”。附能核对该判断的少量脱敏输入/输出、diff或测试/失败片段；完整材料留业务项目，不能分享时说明核验限制，不为补反馈重跑。

把脱敏报告贴回知识库会话，或带回可读取文件。无需自动发GitHub Issue或公开业务仓库。接收后先核版本、基线和证据，决定保持/修订/撤回哪条指导；单项目反馈先入案例层，不自动升级整套原则。
