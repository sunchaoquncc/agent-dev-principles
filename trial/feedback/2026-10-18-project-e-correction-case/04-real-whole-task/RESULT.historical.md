## R1：修复了什么，证明到哪里

问题发生在 Main 已经发现自己的改法不对、尚未实际执行时：分组完成后纠错入口消失；直接调用会确认“已完成”而不更新；随后提交共同合同加两项更正又被拒绝。恢复指引还要求撤回正确修订，导致旧改法继续成为执行依据。

现在复用原审查和合同流程处理：

1. 已完成的普通 Main 分组允许对已审目标提交完整新判断。先在临时状态校验，成功才更新；其余判断不动。改判为保留的目标退出写入集合。
2. 共同合同加少量明确修正，自动承接其他已审目标。冻结后、派发前，以当前执行合同合并；旧计划失效，必须绑定新计划。
3. 缺项、重复或非法修订不污染原状态；只列部分目标且没说明其他目标去向，不能默认为取消。已经派发/写入的事实保持原历史。
4. 程序更新已知的目标、合同和执行计划。修改共同排期后应调整哪些相关业务安排，仍由 Main 判断，没有引入通用依赖图或自动推断系统。

同一原 Trace 中两项修订请求直接重放到本轮不可变基线和最终候选：

| 验证 | 当前优化版基线 | R1.1 候选 |
| --- | --- | --- |
| 完成分组后修订原决定 | 返回已完成，但决定未改 | 新判断被接纳 |
| 共同合同加两项明确修订 | `rewrite_problem_review_scope_conflict` | 成功合并 |
| 原48项任务 | 纠错通路失败 | 修正2项，另外46项改法不变 |
| 旧改法与旧执行计划 | 旧判断保留 | 对应编辑指令使用新改法，旧计划失效 |

此项证明纠错机制的确定性收益，不等于模型每次都会主动纠正，也不等于正文已保存或整案通过。对应证据：`ORIGINAL-CORRECTION-BASELINE.json`、`ORIGINAL-CORRECTION-REPLAY.json` 和真实 SDK handler 测试。最终134项聚焦检查通过。

## 后续问题：已做尝试及定位

### T147 对象、适用条件和具体动作没有同步

场景包括：扩展配送品类后，仍让所有供应商满足肉类专属资格；结算原规则按是否存在公布价选择依据，却被改成按食材类别分配不同价格来源。错误在 Main 的具体改法中已经出现，不能归因于编辑器没有执行。

对同一真实 Main 调用检查点，只替换已加载的核心方法，固定原请求、正文及模型，返回工具均不执行：补充“对象—条件—动作”的 R2 方法后，资格条件遗漏及计价条件误改仍出现。另做同一方法、20候选与单候选材料比较；单候选首先要求调用未提供的读取工具，经一次技术恢复后仍保留错误的旧适用范围。该结果只排除了“增加这段方法说明”及“单纯缩小当前批次”这两种候选，没有证明任何新路线有效，也不把工具限制装置中的恢复问题算线上事故。

R2 已从运行 Skill 撤回，保留原 R1 方法。下一核心问题仍是派生改法能否完整承接用户变更、同时保住独立条件与义务。下一次实验应改变判断任务的组织或合同承接方式，并先在原错误检查点验证，不继续堆同层提醒。是否采用额外拟案调用要先有质量收益，不能直接恢复历史专项或扩大模型调用。

证据：`method-eval-scope/`、`method-eval-conditions/`、`method-eval-batch/`，以及 `method-R1.md`、`method-R2.md`。共7次拿到 usage 的只读调用（含一次技术恢复），已知估算约0.335元；第一次 raw API 装置请求因 SDK Omit 序列化标记返回422，未取得 usage，单列为装置问题，不算模型业务失败。

### T061 工期：当前完整材料版本仍未通过

本轮跑的是 A 基线，899个有效正文小节，实际改5节，全部精确保存回读；约4分33秒，已知 Sidecar 估算约0.649元。没有 R3 新候选，不能作为新版本收益。

本次已读取完整时间导航，保存并传递了共同排期，轮廓标小节进入了修改。仍有以下明确问题：

- Main 将轮廓标安装拟为第176—186天，同时保留“标线完成后第3天才开始”；同一计划中的标线却安排第180—184天。以分段穿插解释也没有给出足以支持早于标线开始就安装的对应安排。
- 养护检测改为第146—151天，按采用的首尾计入口径只有6天，却同时保留不少于7天的要求。
- 表格有持续天数与起止日不一致：护栏改为第170—180天仍写10天；面层和清理行已有矛盾未同步。不是只要结束日不超186就合理。
- 原已见资源供应窗口是否覆盖新的施工安排，仍未形成完整一致方案。

这次缺口已经落在共同计划的推导、机械日期关系与各节合同同步，不能再笼统归为没召回。最小后续方向：先将已读关联工作的起止、持续时间和明确前置条件统一为同一份可核对安排，机械矛盾由工具反馈，业务并行和资源安排由模型判断；在少量已读相关节点通过后，再跑整案。尚未实施此方向，不能把建议计作收益。
