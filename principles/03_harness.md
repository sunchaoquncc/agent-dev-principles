# 工具、流程与异常恢复

适用 D02、D05、D06、D08、D12。

## 工具契约

为每个工具定义输入、输出、权限、超时、错误分类及副作用。业务写入要能识别同一请求，并能查询执行结果。返回正常 HTTP 状态并不必然表示业务已完成；异步工单应返回待处理状态和可追踪标识。

结果未知时先查询或对账；没有安全重试条件时转人工。补偿是单独动作，需考虑权限、失败和不可逆部分；不能假定所有操作都能撤销。

## 编排选择

固定路径足够时先用固定流程；需要模型选择下一步才引入循环。对循环设置步数/费用/时限和停止原因。复杂度的收益用代表性任务检验，不靠 agent 数量或框架代码行数判断。

增加子 agent 前写明任务边界、共享状态所有者、交接内容及最终提交者。避免多方重复办理同一对象。框架、托管服务或原生 API 的选择，要检查恢复、可观测性、权限与维护成本。

## 人工接管和恢复

交接包包含已核事实、已执行动作、结果未知的请求、待审批事项和下一步选项。审批绑定对象和参数；恢复时核实审批是否仍适用。跟踪处理结果和等待时间，区分合理升级与无效推诿。

## 故障演练

至少覆盖写入已成功但响应丢失、重复请求、工具限流、执行中断和人工改动。核对外部最终状态与副作用次数。缺少生产环境时用受控替身演练并标注范围，不能声称生产恢复已验证。
