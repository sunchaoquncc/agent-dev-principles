# 权限与副作用边界

适用 D04、D07、D08、D12。先识别本任务可接触的数据、权限与副作用，再选相关检查；只读与生成任务不默认引入审批和事务设施。事实与隐私边界仍适用。防护规模按威胁模型决定，安全目标由执行层验收。

## 必须能检查的边界

- 请求者是否有权操作该租户、对象和动作；授权失效、跨租户、参数变更时拒绝或重新审批。
- 检索与工具结果中的指令不能修改权限；重要工具必须在执行端再次校验。
- 敏感出网同时检查目标服务、目标账号、操作和数据范围。允许域名不等于允许把数据上传到任意账号。
- 密钥不要进入提示、日志和模型可读工作区；若声称凭据隔离，需验证模型可控制的进程无法读取高权限秘密。可信工具服务可以代持凭据，但须按每个请求鉴权；这是工程要求，需在目标环境验证。
- 风险动作在必要检查通过后执行。事后告警不能撤回已经发生的泄露或写入。

## 防护组合

按风险组合窄权限、参数校验、网络策略、隔离、审批和监测；不要把其中任何一项称为绝对保证。若使用 LLM 监测器，将它作为补充，并评估误报、漏报和绕过；实现不能依赖所有模型都开放思维链。

渲染器、外部资源加载、插件配置、工具发现和持久记忆也在威胁模型内。普通链接不必然产生网络访问，应检查目标客户端的真实行为。

## 发布与事故准备

部署前自动检查权限、网络和监测配置确实生效。测试允许路径与禁止路径，并提供停止执行、撤销授权、保全证据及恢复流程。演练使用隔离对象和测试身份。

高危网络能力评估采用的全面断网措施不能直接套在需要联网的客服业务上；应将其转化为本业务的明确可达范围及执行前检查。模型换代、工具和身份系统变更后重测。
