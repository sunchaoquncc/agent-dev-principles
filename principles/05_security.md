# 权限与副作用边界

适用 D04、D07、D08、D12。先识别本任务可接触的数据、权限与副作用，再选相关检查；只读与生成任务不默认引入审批和事务设施。事实与隐私边界仍适用。防护规模按威胁模型决定，安全目标由执行层验收。

## 必须能检查的边界

- 请求者是否有权操作该租户、对象和动作；授权失效、跨租户、参数变更时拒绝或重新审批。
- 检索与工具结果中的指令不能修改权限；重要工具必须在执行端再次校验。
- 敏感出网同时检查目标服务、目标账号、操作和数据范围。允许域名不等于允许把数据上传到任意账号。
- 密钥不要进入提示、日志和模型可读工作区；若声称凭据隔离，需验证模型可控制的进程无法读取高权限秘密。可信工具服务可以代持凭据，但须按每个请求鉴权；这是工程要求，需在目标环境验证。
- 风险动作在必要检查通过后执行。事后告警不能撤回已经发生的泄露或写入。

## 防护组合

按风险组合窄权限、参数校验、网络策略、隔离、审批和监测；不要把其中任何一项称为绝对保证。若使用 LLM 监测器，将它作为补充，并评估误报、漏报和绕过；实现不能依赖所有模型都开放思维链。

渲染器、外部资源加载、插件配置、工具发现和持久记忆也在威胁模型内。普通链接不必然产生网络访问，应检查目标客户端的真实行为。

Agent 输出会被渲染成 HTML/公式/富文本，或展示面板、导出与告警链路可被 agent 影响时，渲染层按不可信输入处理：保全受保护、可追溯且可核对的原始记录，核阅时对照展示/导出；服务端存储不天然可信，展示视图不能单独证明完整性；此类检查只在对应渲染或影响路径存在时启用，未经过本类渲染的内容无需照搬查看器控制，终端等解释路径按实际风险检查，不默认新增审计平台。

## 发布与事故准备

部署前自动检查权限、网络和监测配置确实生效。测试允许路径与禁止路径，并提供停止执行、撤销授权、保全证据及恢复流程。演练使用隔离对象和测试身份。

高危网络能力评估采用的全面断网措施不能直接套在需要联网的客服业务上；应将其转化为本业务的明确可达范围及执行前检查。模型换代、工具和身份系统变更后重测。


## 验证执行机制与文档承诺一致

工作目录不是文件访问沙箱，命令名字在白名单不表示所有参数和组合都只读；按实际授权检查执行机制。限制返回文本长度，也不等于限制收集过程的内存或所有子进程资源。检查必要日志的真实内容，不能从一个logger的设置推断整个系统不记录敏感数据。以上按工具与数据风险启用，不要求纯文本原型建设系统级隔离平台。

## 泛化型失准与决策历史

两类无需对手的泛化失败要进入威胁模型：跨会话记忆把一次性授权/偏好写成常设规则并在范围外驱动不可逆动作（自写笔记比原始对话更易放大，因笔记在写入时就丢了语境）；同会话内少量带错误模式的示例（哪怕是常见误解而非恶意内容）即可让无关良性问题得到失准回答，且更强模型不一定更免疫、开推理无保护。缓解方向：记忆条目携带形成语境元数据（谁授权、什么场合、适用范围），不可逆动作前按当前有效授权重新确认而非按记忆直接放行；高风险时把记忆当证据而非指令；上下文中显式声明目标优先级（如安全优先）是廉价缓解但非根治。此类检查须按行为（范围外任务测试）审计，文本审查不够。

反过来，只保留最终工件而丢弃"为什么这么改"的决策历史（诊断、被拒方案、依据），会让后续维护者重复旧优化并误读旧取舍——保留决策脉络是可修正性的前提，与防止过度泛化构成同一设计变量的两端：历史保留太少丢依据，太多且无范围标注则放大泛化。

以上为多源研究自报的条件性默认（M-104/M-107/M-110/M-118），全部效果未复现；证据映射与冲突登记见07 v0.22。
