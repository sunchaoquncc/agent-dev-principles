# 通用 Agent 开发记录

适用于不同业务场景，空白模板不代表已验证。先引用现有规格、实现和测试结果，只补与当前决策有关的缺项，可以一页完成；专项只在触发时增加。无需为简单原型先建设治理平台。

## 默认需要的五项

这是五个检查视角，不是五份必交文件。一次性生成或小修复，可合并成任务要求、产物判断和剩余问题几句话；已有代码、提示、日志或测试可直接引用。只对当前改变或要作的效果声明补证据，不为填表新增工具、恢复机制或模型调用。

| 交付项 | 需要写清的内容 | 最小验收 |
|---|---|---|
| 任务样例与质量定义 | 输入、期望结果、失败例、硬约束与质量偏好 | 能判断当前产物是否满足要求，主观项有评判人或标准；用于复用/改进时再保留好坏例 |
| 职责分配 | 每一步由模型、业务代码、编排负责什么及理由 | 没让模型反复做简单转换，也没用脆弱枚举代替语义判断 |
| 提示版本 | 任务、输入含义、决策边界、输出、实际纠正与理由 | 需复用或声称泛化时，用未参与调优的任务检查；一次性粗稿先按当前要求验收 |
| 信息与工具契约 | 来源、表示、字段/数量、加载时机、预算、超限/错误处理 | 检查一条完整模型请求，工具返回有界且关键事实/关系保真 |
| 运行对照与剩余问题 | 配置、输出、错误、实际用量/延迟、修改前后差异 | 有迭代或效果比较时留前后依据；仅交付一次产物时保留验收与未知项，不虚构基线 |

## 按条件补充

| 触发条件 | 补充记录与验证 |
|---|---|
| 有受限数据或权限动作 | 身份、访问范围及执行端检查 |
| 有可能重复产生效果的外部写入 | 幂等/去重/结果查询与未知状态处理 |
| 依赖长任务状态/中断恢复 | 保存范围、恢复方法、外部变更检查 |
| 需要多agent或并发写 | 分工理由、状态所有者、冲突处理 |
| 人工接管是流程一部分 | 交接信息、完成口径、等待成本 |
| 需要用户澄清或持续等待 | 哪些问题改变后续动作、停问条件、可判断的候选、真实工作状态与人工耗时 |
| 使用模型路由或决策分数 | 路由与固定基线比较，检查任务分组和失败去向；分数用于阈值时检验业务错误关系，解释为概率时校准；类型正确不作语义正确 |
| 对外部署或有高后果操作 | 目标环境验收、监测、停机/回退、责任人 |

与本次工作无关的行直接略过；容易被误认为漏检的关键边界才简述不适用理由。读取、生成和离线任务也要检查事实与隐私，但不因此自动增加审批与事务系统。

## 按所用机制补充核对

- 输入有多个版本时：当前权威来源、冲突和缺失是否明确？最终完整请求是否仍保留任务约束？
- 使用按需知识或动态工具时：入口能否定位、相关限制是否及时出现、缺失/截断能否继续读取，工具是否真的可调用？
- 有自动提示优化或评审时：候选修改经过什么回归？评审异常与业务失败是否分开？
- 使用实验数字选型时：版本、判分器、分母和排除规则能否对齐？不能对齐时是否停止效果承诺？
- 用原型对齐选择时：最终代码是否落实选择？临时状态和未实现部分是否标明？

按实际采用的功能检查，无相关机制时不为填表而新增机制。
