# 通用 Agent 开发记录

适用于不同业务场景，空白模板不代表已验证。先填与当前决策有关的部分，可以一页完成；专项只在触发时增加。无需为简单原型先建设治理平台。

## 默认需要的五项

| 交付项 | 需要写清的内容 | 最小验收 |
|---|---|---|
| 任务样例与质量定义 | 输入、期望结果、失败例、硬约束与质量偏好 | 能判断一例成功和一例失败，主观项有明确评判人或标准 |
| 职责分配 | 每一步由模型、业务代码、编排负责什么及理由 | 没让模型反复做简单转换，也没用脆弱枚举代替语义判断 |
| 提示版本 | 任务、输入含义、决策边界、输出、实际纠正与理由 | 在其他任务上检查是否过拟合首个样例；样本量随风险增加 |
| 信息与工具契约 | 来源、表示、字段/数量、加载时机、预算、超限/错误处理 | 检查一条完整模型请求，工具返回有界且关键事实/关系保真 |
| 运行对照与剩余问题 | 配置、输出、错误、实际用量/延迟、修改前后差异 | 有可回放证据，能解释下一步改哪一层；不声称已找到全局最优 |

## 按条件补充

| 触发条件 | 补充记录与验证 |
|---|---|
| 有受限数据或权限动作 | 身份、访问范围及执行端检查 |
| 有可能重复产生效果的外部写入 | 幂等/去重/结果查询与未知状态处理 |
| 依赖长任务状态/中断恢复 | 保存范围、恢复方法、外部变更检查 |
| 需要多agent或并发写 | 分工理由、状态所有者、冲突处理 |
| 人工接管是流程一部分 | 交接信息、完成口径、等待成本 |
| 需要用户澄清或持续等待 | 哪些问题改变后续动作、停问条件、可判断的候选、真实工作状态与人工耗时 |
| 使用模型路由或决策分数 | 路由与固定基线比较，检查任务分组和失败去向；分数用于阈值时检验业务错误关系，解释为概率时校准；类型正确不作语义正确 |
| 对外部署或有高后果操作 | 目标环境验收、监测、停机/回退、责任人 |

不适用项注明简短原因即可。读取、生成和离线任务也要检查事实与隐私，但不因此自动增加审批与事务系统。
