# 上下文层细则 v0.2（2026-10-13）

对应核心层规则 8—12。证据见 notes/（M-002/M-003/M-017），条目定义见 graph/overview.md。本层是四批信源的主战场，认可级密度最高。

## 规则 8：上下文是预算 ✅ [M-007/K-002]

**做什么**：把上下文窗口当预算管理——只放高信号 token；能用指针（URL、文件路径、查询语句）替代的全文一律指针化；每次往窗口里加东西前问"下 N 步真的需要吗"。

- 机制依据：context rot——token 增长→中置信息回忆与推理退化（needle-in-a-haystack 谱系；机制假说：平方级注意力+短序列训练偏置，M-002）；两家独立声明窗口扩容不豁免（ECE"context pollution" + Manus"窗口再大也不实用"）。
- **本地复现边界（2026-10-13，E-02/E-02b，glm-4-flash）**：单针 30/30、同型干扰针 24/24 全中——**≤12k token 档的检索类 rot 已在该代模型饱和**；本规则的强制力现主要来自成本恒在 + 超长窗口/聚合推理/生成型退化三个未饱和域。引用"rot"论证时注明适用域。
- 成本依据：Manus 输入:输出≈100:1，缓存价差 10x（K-003）。
- **共同内核 vs 处方分歧**（重要）：认可的是"治理不可省+高信号+指针化"；裁剪方式两派相反——ECE 裁剪窗内（compaction 摘要替换历史），Manus append-only+状态外置文件系统。选型参考任务形态：对话流多轮→compaction；长循环/文件系统友好→外置+可恢复压缩。
- 具名冲突（D1）：ECE 把清除旧工具结果平台化（tool result clearing）vs Manus 要求失败轨迹留在上下文——见规则 12。

## 规则 9：长任务状态外置 ✅ [M-014]

**做什么**：目标、计划、todo 写成文件（如 todo.md）；每个动作前复述进上下文、放末端（注意力热区）；跨压缩/跨会话的状态靠文件不靠对话历史。

- 机制：对抗 lost-in-the-middle（复述到末端，Manus）；跨 compaction 存活（Pokémon 案例："After context resets, the agent reads its own notes"，ECE）。
- 两家机制各背书一半（持久性=ECE，注意力位置=Manus），实践同构；Cognition"上下文连续前向流动"是第三方呼应（M-017）。
- **本地对照（2026-10-13，E-04，glm-4-flash，N=6/臂）**：要求清单末端重注入 4.7/8 vs 前置 3.8/8——方向性支持；**约束分层发现**：格式类约束（前缀/结尾/句数）两臂全过=位置无关（饱和），词频类（含指定词≥N 次）重注入有利（4/6→6/6），抑制类（禁用背景资料中的干扰词）与计数类（恰好 N 段）是弱模型短板、位置改善有限。复述机制的收益集中在内容类约束。
- 厂商内置化风险最高条目之一：memory tool 已公测（K-005）——触发器命中时改用官方记忆。

## 规则 10：检索 just-in-time ✅（细则双向）[M-009]

**做什么**：轻量标识符（文件路径/查询/链接）先行，运行时按需取全量；渐进披露（先目录后分页）；目录结构、命名、时间戳本身是信号（metadata 即上下文）；与少量预置文档（如 CLAUDE.md 类）hybrid。

- **代价（原文双向呈现，别只看一半）**：agentic search 更慢、可能浪费上下文追死胡同、需要引导；动态性低的内容用预置文档更好（ECE 原话："The hybrid strategy might be better suited for contexts with less dynamic content"）。
- 适用条件：文件系统友好任务域（编码/研究检索）；对话域证据未覆盖。

## 规则 11：KV-cache 优先 🧪 [M-011/K-003]

**做什么**：prompt 前缀稳定——时间戳等易变内容后置或隔离；对话历史 append-only；长共享前缀显式设缓存断点 [外注：Anthropic API 上限 4 个]；把 KV-cache 命中率当生产第一指标监控。

- 证据：Manus 单源（候选级），但经济性可验（$0.30 vs $3.00/MTok，与官方计价一致）；[我方推导]按 100:1 牌价输入占成本 2/3—95%，收益与命中率强相关（E-05 可验）。
- 张力：与提示迭代（规则 5）工程摩擦——迭代期与发展期分开部署。

## 规则 12：失败轨迹留在上下文 🧪 [M-015/M-013/M-010]

**做什么**：失败尝试（含报错、stack trace）不删——错误恢复是最 agentic 的能力之一（三源同向说它是核心指标，K-006；"保留"处方是 Manus 单源）；压缩必须可恢复：丢网页全文保 URL、删中间文件保路径。

- 与规则 8 的调和：判据是"高信号"不是"少"——错误轨迹是反馈信号，冗余才是要删的。
- 过激警告：ECE 自警"overly aggressive compaction can result in the loss of subtle but critical context"，调参先 recall 后 precision（M-002）。
- 长时程三板斧选型（M-010，候选）：compaction=对话流多轮；结构化笔记=有里程碑的迭代；子 agent 隔离=并行探索研究型（只读检索子 agent 是三方公认的第一个适用域）。
