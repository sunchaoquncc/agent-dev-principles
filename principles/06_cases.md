## 通用性压力测试（我方设计，非运行结果）

这些场景用于检验原则能否迁移，不构成知识库业务范围或固定模板。

| 任务 | 核心开发决策 | 能否看出原则有用 |
|---|---|---|
| 网页资料分析 | 正文/表格/链接如何表示，何时取详情，依据如何回查 | 能去无关页面结构且不丢关键关系；不把纯文本最短当最佳 |
| 长文改写 | 哪些事实/关系必须保留，哪些风格可改，全文或分段 | 提示有可判断边界；分段后能发现跨段矛盾 |
| 开放内容生成 | 读者、目的与质量偏好，是否需事实素材或规划 | 结果按实际质量评判，不强塞交易型完成状态 |
| 客服咨询/办理 | 语义理解与明确政策、检索、业务操作的分工 | 咨询无需事务框架；办理才增加相关授权/重复操作处理 |
| 数据分析 | 模型解释问题，代码计算，编排供给适量数据 | 不把整表塞入提示让模型手算，也不把语义结论交给机械阈值 |
| 代码修改 | 模型提出实现，代码工具执行，编排提供相关文件与验证 | 只加载相关依赖，能检查实际行为，而非把全部仓库反复输入 |

若一条原则只能在其中一个特定领域成立，归入条件专题；若只是口号、不能改变任何设计或验收，也不留在核心。

## 客服成本优化：可借用测量流程

OpenAI 的客服教程覆盖查询、政策敏感处理及人工升级，用相同任务比较质量和成本。默认路径采用合成工单、模拟工具与建模指标，不能从演示数字推断实际模型能力或生产节省。

不可迁移：固定模型分工、模拟收益、关键词评分器直接作为业务正确性标准。

## 应用示例：客服取消订单（我方设计，非来源实测）

业务方需先确定谁可取消、哪些状态可取消及是否需审批。此处不预设具体政策。

| 输入或故障 | 系统动作与验收 |
|---|---|
| 有权限且符合有效政策 | 执行后查询订单最终状态；确认取消后才告知完成 |
| 请求取消他人租户的订单 | 执行端拒绝；无状态变更、无泄露 |
| 政策缺失或冲突 | 查权威源或转交；不猜资格 |
| 写入成功但响应超时 | 根据请求标识查状态；不重复副作用 |
| 等待人工审批时订单被修改 | 重新核对条件与审批适用范围 |
| 转人工 | 传递已做动作、未知结果和证据；跟踪最终解决 |

## 近期访谈补充：做法与反例一起保留

- **Pocock的规划方法**：他对大型、回退昂贵任务先对齐，却明确说小型可逆改动不必都做需求访谈，也会先做原型再形成规格。可迁移的是按不确定性与改错代价选择反馈方式；不是所有任务都采用问卷、票据和TDD。个人经验，未做流程效果对照。
- **Appleton的设计原型**：让人直接调节可视工件，帮助表达难以口述的偏好；同时报告写入Skills的偏好仍未一致执行。可迁移的是提供可判断的反馈材料并观察实际行为；不能凭此认定所有澄清都要GUI，或原型的代码质量门槛可照搬生产。
- **Cornell的交互设计**：区分任务正在做什么与按需展开的细节，用户组织会话的方式也不等同于后端把全部历史发送模型。属于设计者经验；本次只读文字，没有验证画面与用户效果。
- **Lindquist的语音待办**：有限对象和操作可由模型逐步匹配、由函数执行。演示没有证明分数经过校准或动作安全；类型正确不代表语义正确。开放写作不必改造成固定动作菜单。
- **Newman的重复请求**：参数相同不代表同一业务意图，超时也不证明写入失败。此经验只迁移到相关副作用接口，不给纯生成任务增加幂等平台。

## 上下文与记忆：方法成立需要运行证据

RLM访谈的反例：推动者自己仍在多数情况倾向压缩，Prime也混用压缩与外部回查；更多并行候选可能没人阅读。可用于检查复杂结构、局部指标和实际消费成本，不能把该个人偏好反过来变成“永不使用RLM”。

CLM的ContextBench刻意禁止入模前处理，用于诊断窗口内管理；这类实验条件不应照搬成业务输入管线。生产可先解析HTML或筛选字段，再按任务比较摘要、全文或外部回查。模型自估预算和同轮限也不能替代真实token、调用、时间统计。


记忆教程的页面把组件配置和手写输出摆在一起，但未连起最终运行、压缩后继续和下一次消费；这是“代码可读”与“能力已运行”的区别。重复运维轨迹转成解析器的案例则出现固件更新后退化；能检测到异常后回退，不代表静默误解析也会被发现。两者用于限定演示与确定性带来的信心，未否定相应设计路线。

E248的岗位Agent要衔接订单、配件、履约等既有系统；“提醒发货”并非只写一句回复。嘉宾自述某次部署持续一年多、模型升级需业务再验证，限制了“像雇成熟员工一样即插即用”的比喻。这是供应商匿名经验，不是部署工期或升级收益的普遍标准。

晚点178的研究参与者先选短反馈基准，明确承认小规模向大模型迁移有缺口，核心系统和搜索预算未完整披露。它支持把可执行候选与外部测量联系起来的案例，不能证明业务Agent改prompt、追加记忆就实现了递归改进。反馈快、评价器可信、迁移有效是三个不同问题；采用自动改进时沿用已有候选验收要求，不因科研愿景扩大权限或自建训练平台。来源日期及限制见07证据附录。

## 评分器可靠性、真值审计与监督链路（第十五批）

- Jev比较（5个冻结案例、各100次）：作者归档摘要显示Jev方差最低，但连续quality距离该人工oracle数值最大；另一judge在Springfield 100次与oracle不一致且binary方差为零。MAE/方差等只核作者摘要及加权关系，无逐trial数据，不称独立重算；两份澄清产物的模式不证明任意反问规律或字段未被使用。可借同输入重放和波动/一致率分报，不复制模型排名。
- Google难度扫描（厂商自报，无公开实现）：查询变体得分、真值损坏与生成器分歧提供审查线索；增删术语可能改变任务含义或可接受答案，不能自动固定旧真值。数值未独立复算。
- METR查看器PoC：原数据库未动而显示/下载可被改写，支持分开保护原记录与视图。作者报告具体漏洞一天内修复；另核#5566为可选untrusted mode，不能等同漏洞补丁或所有部署已安全。
- Cloudflare历史工程快照（数据03-10—04-09）：专项模型提发现并标级，协调模型负责去重/严重性核实/终判，代码负责按diff路由资源和超时/熔断/回退。低findings量与负向提示边界的联系为作者解释；$1.19为另项全系统观察，不据此归因降本。两处明细/总数冲突未解释，缺人工质量标注、原始数据和同例前后产物，不当现行效果证明。

## 项目E：输入更短之后，整条消费链仍需兼容

**任务与基线。** 已有多轮工具、输入投影和恢复机制的文稿Agent；比较A=e3a0626d（已优化版）与B=c65a129f，采用本库v0.13。以下是2026-10-16获准分享的项目报告；本库核读报告及字节算术，未取得私有代码/断言/测量脚本，未复现运行。

| 观察到的问题 | 项目实际选择及未采用路线 | 结果与取舍 |
|---|---|---|
| 参数引用化后，恢复包装仍依赖已消失字段，模型调用前崩溃 | 修规范化顺序，保留原参数和分页回查；没有将全部历史重新常驻 | 报告B能构建请求；未证明提供方接受、模型会回查或最终任务完成 |
| 缩批替代事实没传到投影；清理后旧快照可能复活；同对象换句柄后预算不承认有效进度 | 原状态所有者提供替代事实，消费端沿用；承接合法身份替换但不增加预算上限 | 报告组合保护例通过；是代码/状态结果，未测用户耗时或正文质量 |
| 缺字段、非对象JSON和内部故障共用错误反馈，并一律缩批 | 根据真实原因反馈，保留已接纳部分；保持首次批量，没有采用统一更小批次 | 报告减少不相关恢复动作；真实模型额外轮数仍未测 |
| 扩展回归出现旧错误类别兼容失败 | 保留原公开错误类别，增加子类型，减少不必要兼容变化 | 修改后报告回归通过；说明第一版方案仍需修正，不能只保留最终正结果 |

**前后结果分开看。** 一个合成缩批检查点的HTTP请求76,438→56,365字节，算术减少26.26%；7份真实历史的首轮重建请求A/B逐个持平。定向12断言A通过1项、B通过12项，B的278相关回归通过，均为项目报告，不是随机业务成功率。A自身开关投影的85.02%—94.94%变化是另一个对照，不能计成B收益。

**采用边界。** 报告的工程候选可回退，未发布生产；没有新建摘要Agent、检索平台或第二执行循环。真实模型调用为0，真实token、费用、正文质量未测；开发助手与人工投入未知，总开发成本不能写0。历史建议与本轮测试分开。

**对下一项选择的启发。** 对同类表示故障，可先沿实际受影响的消费链确认兼容性，再决定是否改表示或补信息；这是我方条件性迁移，不保证适用于其他项目。仅当下一步要改变批量或引用呈现时，再验证模型实际取用与任务质量；已有工程决定不因追求漂亮报告而重跑模型。

出处及原报告链接见07；私有实现留原项目。案例的价值是可看清改动、未采用方案、退化和未知，不是证明这套指导比等量普通调试更好。
