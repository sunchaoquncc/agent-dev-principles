# Agent 开发核心原则（给开发用的 AGENTS.md）

一套可直接加载进 agent 开发会话的开发原则：**22 条规则 + 反模式 + 复核触发器**，按"三层 + 两横切"组织（prompt 治理 / 上下文治理 / harness 治理 + 评测 / 安全）。

## 怎么用

1. **最简用法**：把根目录 `AGENTS.md` 复制到你的 agent 开发项目根目录（多数 agent 工具会自动加载根 AGENTS.md），或粘贴进系统提示。
2. **渐进式披露**：核心文件只放必看的薄层（22 条规则）；细则在 `principles/01—05` 按需读，不要全量加载。`principles/06_cases.md` 是案例索引。
3. **徽章含义**：✅=认可（≥2 独立来源收敛）；◐=有条件（多源相邻收敛或窄适用）；🧪=候选（单源经验断言，试用）。**🧪 条目用前自查，别当定论。**
4. **元规则**：这些原则绑定验证日期的模型代际（2026-10）。触发器命中（模型大版本、厂商内置化、复现失败、基准更替、6 个月例行）时先复核再沿用；引用数字前查原始条目。


## 出处与维护说明

- 构建于 2026-10-13，蒸馏自 12 个一手信源（Anthropic 两篇工程文、Manus、Cognition 原文+自我修订、Amp、OpenAI 实操指南、SWE-agent 与 Agentless 论文、METR 时长域研究、Simon Willison 注入分析），每条规则带证据链与适用条件。
- 规则中的 `M-xxx / K-xxx / Q-xxx` 编号指向未随本仓库分发的私有知识库（信源笔记、引文校验记录、快照存档）。编号保留作溯源标签；需要证据链时可按编号在私有库查证。
- 原则状态与徽章基于"≥2 独立来源或 1 源+复现"的蒸馏门槛；单源条目一律标 🧪 不冒充共识。
